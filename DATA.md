## Which dSPM state file each decoding panel uses

The two `dspm_states_normalized_1000neurons.mat` files are different and both are used, exactly as in the runs reported in the paper:

| File | Masking | Used by |
|---|---|---|
| `data/dspm_states_normalized_1000neurons.mat` | none after the trial's end (0.75% NaN) | Fig. 3C `ftp_decoding_pipeline.m`, Fig. 3E `bounce_subspace_ftp_decoding_pipeline.m` |
| `scripts/decoding-analysis/data/dspm_states_normalized_1000neurons.mat` | NaN after each trial's last valid bin (37.6% NaN), like the neural, RNN and Ball State inputs | Fig. 3F `svm_bounce_pipeline.m` |

`mtp_decoding_pipeline.m` (Fig. 3D) keeps its loads inside `if 0` and uses the variables already in the workspace. The saved `mtp_data_output/` predates the masked file, so it was computed with the unmasked one: load `data/dspm_states_normalized_1000neurons.mat` as `dspmStates` before running it to reproduce Fig. 3D. Neither file is regenerated by the current `preprocessing/dspm_run_state_normalization.m`, which writes a third version into the run folder; both are shipped in the data release.
